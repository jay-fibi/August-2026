Comments & Best Practices

Comments <!-- like this --> are ignored by the browser but invaluable for humans reading your code.

Lesson 16 Beginner

💡 The Concept

  • Comments start with <!-- and end with -->. Everything between them is invisible to visitors.
  • Use them to explain why a section exists, mark TODO items, or temporarily disable a block while debugging.
  • Comments cannot nest — the first --> ends the comment.

Best practices to keep your HTML maintainable:

  • Indent nested elements consistently (2 spaces is common).
  • Use semantic elements instead of generic divs.
  • Write descriptive alt, title and label text.
  • Keep lowercase tags and quote your attribute values.
  • Comment before complex sections — but delete stale comments.

📝 Source Code

How comments look in source 
<!-- ================= -->
<!-- Product card      -->
<!-- TODO: add sale price -->
<!-- ================= -->
<section class="product-card">
  <h3>Product Card</h3>
  <button type="button">Add to cart</button>
</section>
<!-- /Product card -->
💡 Best practice: Comment the why, not the what. A comment saying <!-- nav starts here --> adds nothing; one explaining a browser quirk saves future debugging hours.

✅ Key Takeaways

Remember

  • Comments use <!-- ... --> and never render.
  • Explain why, not what; remove stale comments.
  • Keep markup lowercase, indented, quoted and semantic.
  • Consistent structure is the foundation of maintainable HTML.
