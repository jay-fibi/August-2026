Accessibility (a11y)

Building for everyone means making your HTML usable by screen readers, keyboard-only users and people with colour vision deficiencies — accessibility is a feature, not a bonus.

Lesson 18 Intermediate

💡 The Concept

  • Use native elements — a real button or a gives focus and keyboard support for free. Don't fake a button with a div.
  • alt on images and label on form fields — screen readers announce them.
  • ARIA (aria-label, aria-hidden, role) — fills gaps only when native HTML can't express something. "No ARIA is better than bad ARIA."
  • Keyboard navigation — every interactive element should be reachable with the Tab key and triggerable with Enter/Space.
  • Colour contrast — text must contrast with its background (WCAG AA: 4.5:1).
💡 Quick wins: descriptive link text ("Read the tutorial" instead of "click here"), one h1 per page, and a logical heading order.

Accessible pattern 
<label for="name">Your name:</label>
<input type="text" id="name" name="name"
       required
       aria-describedby="name-hint">
<small id="name-hint">As shown on your ID card.</small>

<!-- Decorative icon: hidden from screen readers -->
<span aria-hidden="true">✨</span>

<!-- Descriptive link text -->
<a href="tutorial.html">Read the tutorial</a>

✅ Key Takeaways

Remember

  • Prefer native elements — they bring keyboard and screen-reader support for free.
  • Always provide alt, label and descriptive link text.
  • Use ARIA sparingly and only when native HTML can't do the job.
  • Test with keyboard (Tab + Enter) and check colour contrast.
